# Worker 03 — Package ISF FX à une passe

Lis le README du coordinateur et les types/appels remis par 01. Mission : livrer un vrai package local `.sgplugin.json` avec contributions `importer` et `exporter` pour le sous-ensemble ISF FX à une passe. Un import aboutit à une définition d'effet `custom` intégrable dans un shader ; un export produit un `.fs` ISF que le même sous-ensemble peut réimporter.

**Lancement.** Attends l'acceptation/intégration de 01 **et** celle du jalon d'effets sur `develop`. Le coordinateur fournit `<launch_sha_03>`, identique au SHA de lancement de 02. Crée `codex/plugin-isf-03` dans le worktree sibling `shader-studio-plugin-isf-03`, vérifie le statut propre. Livraison `integration-only`, base `integration-tip` ; ne modifie pas l'UI Installed ni le stockage appartenant à 02.

**Propriété.** Source du convertisseur et package émis sous `tools/workspace/fixtures/plugins/isf/` (ou un package workspace dédié), specs qui l'invoquent via le vrai `PluginHost`, raccord limité avec `apps/web/src/app/ui/workspace-actions.ts` ou un nouveau service d'application d'effet. Les trois fixtures ISF indépendantes (couleur, UV décalés, contrôles) font partie de cette propriété. Ne mets pas le convertisseur dans le bundle principal de l'app : le package doit être réellement chargé par 01, pas invoqué directement comme code de confiance.

**Sous-ensemble.** Accepte seulement `inputImage` FX, une passe, entrées `float`/`bool`/`long`/`color` représentables en `ShaderControl`, et les variables/fonctions ISF nécessaires aux trois fixtures. Définis explicitement les macros acceptées ; ne réécris pas du GLSL arbitraire par remplacements textuels qui peuvent toucher commentaires, identifiants ou chaînes. Une syntaxe non représentable produit un diagnostic précis et aucun changement du projet. Traduis vers `vec4 effect(vec4 color, vec2 uv)`, puis fais valider la définition par l'hôte avec les contrôles et limites du modèle existant ; une compilation candidate doit réussir avant d'adopter l'effet. Garde le code et les valeurs dans la définition embarquée, avec provenance facultative du package. Les exports `.fs` sont produits par le Worker comme source GLSL bornée, puis sélectionnés/sauvés par l'hôte ; aucune sortie HTML/JS.

**Refus explicites.** Générateur, transition, second input image, audio/FFT, point2D/event, imports de fichier, PASSES multiples ou persistants, version ISF non comprise, source hors limites. Un échec de conversion/compilation laisse le shader et le fichier de destination intacts. Pour le sous-ensemble accepté, vérifie import → réglage → export → réimport, valeurs, labels, min/max et rendu. Source de référence : [spécification ISF](https://docs.isf.video/ref_json) et [fonctions ISF](https://docs.isf.video/ref_functions.html).

**Vérification.** Specs ciblées du convertisseur et du package via le host de 01 ; `pnpm --filter @shadergrove/web typecheck`, puis essai navigateur des trois fixtures si disponible. Couvre AC-ISF et les chemins d'erreur d'AC-PACKAGE. Relis le diff complet, fais 1–3 commits, rapporte base/HEAD, commits, chemins, checks, risques et limites exactes du sous-ensemble. Aucun push ni PR.
